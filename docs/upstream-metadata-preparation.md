# Optional upstream metadata preparation

Registration supplies a disabled `ops.upstream_source_drift_runtime_policy`
preparation policy and durable cursor. The installation operator assigns the
owning record, owner, integration/deployment owner, bounds and optional priority
keys before explicitly enabling the capability. The default owning record here
is a documentation placeholder, not an assigned running agent.

`whiteroom:monitor --prepare --format=json --compact` records bounded source
checks and creates distinct backend preparation records for changed revisions.
Failures remain inconclusive with retry timing; cursor rotation reserves space
for other sources even when priority watches keep failing. It preserves existing
owners, deferred work, previous conclusive receipts and source identity. It does
not install dependencies, download models, run source workers or publish changes.

The `upstream_public_metadata` profile grants only this named task's approved
HTTPS GET endpoints and exact query shapes for GitHub repository metadata,
Hugging Face model metadata and arXiv identifiers. It carries no generic tool,
provider, MCP, domain or path permission. Existing internet, offline, parent
profile and network restrictions still apply; redirects and response bodies are
bounded. Remote metadata is evidence to review, not proof of license or adoption
permission.

Public registration preserves an existing scheduled definition until preparation
is explicitly enabled. The separate scope migration changes only a matching,
already-enabled registered preparation policy. Rollback preserves cursor,
receipts, unfinished work and operator overrides.
